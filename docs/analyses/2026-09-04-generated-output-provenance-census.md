# 2026-09-04 — Generated-output provenance census (issue #239 sub-question 2)

**Dated snapshot at master `a4e24bc`** (and, for the upstream-heritage split, the
historical commit `1f6ac950`, 2016-02-21, where `adigator.m` first appears).
Per the [`README`](README.md) rules: immutable once merged; live tracking is
[#239](https://github.com/pdlourenco/adigator-embedded/issues/239); `file:line`
references are relative to `a4e24bc` and are expected to drift.

**What this answers, and what it does not.** #239 asks what licence a generated
derivative carries and names one sub-question as engineering work:
*does any ADiGator-originating text land verbatim in generated output?* This
census answers that, inventories the emission surface, and — because the answer
turns out to be actionable — assesses which of the "staining" this fork can
reduce unilaterally. It is **not a legal position** and takes none: whether the
output's *structure* makes it a derived work (sub-question 1) is exactly the
question this document refuses to answer, per the issue's own warning that a
confident engineering answer dressed as a legal one is worse than silence.

**Method.** Static. Generated output is produced entirely by `fprintf`
templates in the tool's source (1,265 `fprintf` lines across 82 files under
`lib/`, `util/`, `embedding/` and `adigator.m` — one count, one population; a
majority are console echo, separated by inspection of the target fid). The census enumerates the emitters — which covers every output mode by
construction — and validates the classification against the committed
generated artifact `tests/fixtures/gen_dialect/slim1/gapfun_Grd.m` (140 lines,
generated 2026-08-04, in-tree since #240), mapped line-by-line to its emitting
sites. No MATLAB was used; §6 lists what a MATLAB pass would add
(*confirmation breadth, not coverage*). The `tests/fixtures/collapse/` pair
was deliberately **excluded** as ground truth: those files are hand-written
synthetic mirrors of the classic dialect (their own headers say so), not tool
output.

---

## 1. The three provenance categories

Every emitted fragment falls into one of:

1. **User-derived** — the user's variable names, their statements echoed into
   comments, and numeric data computed *from* their function (derivative
   patterns, index tables, sizes). This is the bulk of every generated file.
2. **Scaffolding** — MATLAB syntax and punctuation, the `cada*`/`Gator*`
   naming scheme, single-line functional templates (`for %s = 1:%d`,
   `%s = zeros(%d,1);`, the `%#codegen` pragma). Short, dictated by function,
   with no room for expressive choice.
3. **Tool-authored text landing verbatim** — prose and multi-line fragments
   written by a person into the tool's source and copied into every output.
   This is the category sub-question 2 asks about, inventoried in §2.

The classification of 1–2 vs 3 is an engineering judgement about *origin and
expressiveness*, not a copyright ruling — but it is the inventory any later
ruling would need.

## 4. The two findings that are more than comments

**4a. The 2-D interpolation path makes generated code *depend on* the GPL
library at runtime — and plain `interp2` is enough to trigger it.** Six
emission sites print a call to `adigatorEvalInterp2pp` (which resolves to the
plain library function `lib/adigatorEvalInterp2pp.m`) into the derivative
body: `lib/@cada/adigatorEvalInterp2pp.m:232`/`:241`/`:350` and — the larger
population — `lib/@cada/interp2.m:210`/`:219`/`:328`, the overload of
**MATLAB's own `interp2`**. A user who differentiates a function containing
an ordinary `interp2` call ships output that does not run (or codegen)
without a GPL library function on the path — `interp2.m`'s own docstring says
as much. This is sub-question 3 of #239 (the runtime-library-exception
question) made concrete, and it is the *strongest* coupling found: not text
similarity but an actual dependency. No emitted call to any other library
function was found. *(The first committed draft claimed the scope was "only
user functions that call `adigatorEvalInterp2pp`" and recorded the very grep
that disproves it without having run it as recorded — the analyses-README
failure verbatim, caught by the §2 pre-push review. The corrected scope is
strictly worse for the licensing question, which is why it matters.)*

**4b. Classic mode ships ~5 lines of upstream-authored executable loader
code** (block 9). Trivial and purely functional (`global` + `load` + guard),
but it is the one place upstream-authored *code* — not comments — lands in
output. Embed modes (`'l'`/`'i'`), the modes this fork exists for, do not
emit it.

## 5. How CasADi handles the same problem (verified at source)

CasADi — a source-generating AD tool, **LGPL-3.0** — was read at
`casadi/casadi` commit `317c67e`. Its generated-file banner
(`casadi/core/code_generator.cpp:460`) is, verbatim modulo the
closing `*` line and trailing whitespace:

```c
/* This file was automatically generated by CasADi <version>.
 *  It consists of:
 *   1) content generated by CasADi runtime: not copyrighted
 *   2) template code copied from CasADi source: permissively licensed (MIT-0)
 *   3) user code: owned by the user
 */
```

Three things worth taking from it:

1. **It enumerates provenance categories in the output itself** — the same
   three this census found independently — and assigns each a position.
2. **The staining category is dual-licensed at the source.** The template
   code that lands in output is declared MIT-0. Verified at file level for
   the interface runtimes (e.g. `casadi/interfaces/ipopt/ipopt_runtime.hpp:1–12`
   opens with the full "MIT No Attribution" grant naming Andersson, Gillis,
   Diehl, KU Leuven); the core `casadi/core/runtime/*.hpp` snippets carry no
   per-file licence header (only a lint pragma) and rest on the banner-level
   declaration — noted as observed, since that asymmetry is upstream's to
   explain, not this document's.
3. **They could do this because they own the templates.** The MIT-0 grant is
   signed by the tool's own copyright holders. That is precisely the lever
   available and not available here, split in §2's Author column.

The GCC Runtime Library Exception and Bison's output exception (both already
named in #239) are the same move at heavier weight; CasADi's is the
closest-in-kind model — a modern codegen tool, copyleft-licensed, whose
output banner settles the question in six lines.

## 6. Can the staining be reduced? — the engineering answer

Split by the §2 Author column, because that is what determines who can act.

**Fork-authored blocks (1–4, 8): yes, unilaterally, and they are the bulk.**
~30 of the 37 stained lines in the fixture are fork-authored (© Lourenço/GMV,
2025–26). On the engineering facts assembled here, the fork appears free to
do the CasADi move for those lines — state in the emitted header that the
fork-authored header/banner text itself is not subject to a claim (MIT-0 or a
plain no-claim sentence), and/or adopt a CasADi-style provenance enumeration
in place of prose — with one recorded caveat carried down from §2: block 2's
notice echoes the *ideas* of upstream's disclaimer in fork wording, and
whether that echo matters is a judgement for the legal step, not this one.
This would leave the *fork's* contribution to the output explicitly
unencumbered. **§4 note:** the emitted header is user-visible and
licensing-adjacent — changing it is a maintainer decision and, if taken,
belongs in an ADR beside ADR-0038; nothing is recommended into existence
here.

**Upstream-authored comment conventions (5–7, 12): reducible by rewriting,
if desired.** These are four short functional phrases (~7 lines in the
fixture: three body markers, three call markers, one preamble phrase). The
fork may modify the GPL tool freely; text the fork writes *from scratch* is
fork-authored, while whether a close rewording of an existing phrase clears
the same threshold — and whether the current five-word phrases are
protectable expression at all — is exactly the judgement this document
declines. The engineering fact is only this: the upstream-authored *text* in
output can be driven to zero-or-arguable for ~7 lines of churn per generated
file. **The churn is not
free**: the `Start Derivative Computations` marker is matched by at least
seven engine files (`git grep` at `a4e24bc`: `adigator.m` — whose
re-differentiation path *matches* it at `:360`/`:449` (a consumer; the sole
emitter is `adigatorFunctionInitialize.m:1040`) — `adigatorParseTape`,
`adigatorForwardTapeSlice`, `adigatorFieldSlice`, `adigatorGenRevGradFile`,
`adigatorPeepholeUnionCopy`, `adigatorSlimDerivBody`/`File`), so rewording it
is a generated-dialect change with fixture recapture and test consequences;
`%User Line:` is emitted from three sites, and the `Call to function` and
preamble phrases from two more — none of whose consumers have been enumerated
the way the body marker's were; that enumeration is owed before any rewording
PR. An earlier draft of this paragraph named only `adigatorParseTape` as the
body-marker consumer — wrong twice, understating the blast radius and
misplacing it.

**The two hard residuals: not reducible by text edits.**

- **The 2-D interpolation dependency (4a) — six emission sites, reached by
  plain `interp2`.** Options, all with costs: (i) inline the evaluator's
  body into generated output — *worse*, it copies upstream GPL code verbatim
  into the artifact; (ii) refuse the construct under embed modes with a named
  id, making the dependency loud (cheap, honest, narrows the tool); (iii) the
  real fix, which is upstream's blessing over this one function — and this
  census reduces #239's "ask upstream" step from an abstract licensing
  question to a concrete, two-item list: *the `adigatorEvalInterp2pp` runtime function
  (reached from ordinary `interp2` calls, so not a niche path) and
  the classic loader trailer*.
- **Structure (sub-question 1).** After every text-level reduction above, the
  output's shape — the two-pass dialect, the naming scheme, the index-table
  discipline — still originates in the tool. Whether that alone makes output
  a derived work is the bison/gcc question, unanswerable from this repo, and
  untouched by any of the reductions. What the reductions achieve is making
  the *text* half of the question empty, which is what CasADi's banner
  presupposes when it says "user code: owned by the user".

**Net:** in the embed modes this fork exists for, after the unilateral moves,
tool-authored content in a generated file would be: a provenance banner the
fork explicitly disclaims, zero-or-arguable upstream-authored text, and — on
the 2-D interpolation path — one library call that the fork can only guard,
not free.

## 7. What a MATLAB pass would add (confirmation, not coverage)

The census enumerates emitters, so every mode is covered statically. A
Coder-licensed session can confirm the classification empirically in
minutes; recording the commands per the analyses-README rule (each was
designed against `a4e24bc`, not run — there is no MATLAB here):

1. Generate one artifact per mode — classic `'c'`, coderload `'l'`, inline
   `'i'` × {`adigatorGenJacFile`, `adigatorGenHesFile`,
   `adigatorGenRevGradFile`} — and diff every comment line against §2's
   inventory: any tool-authored line not in the table is a census miss.
2. Generate a function calling `adigatorEvalInterp2pp` and confirm the
   emitted runtime call (4a) and its codegen behaviour under
   `adigatorCoderConfig`.
3. `grep -c` the emitted files for `mweinstein|sourceforge` (expect 0 — #240's
   negative assertions already pin this in `UGenerationStampTest`).
